# Architecture

Hermie is one Starlette app (`hermie/proxy/server.py`) with a single route, `/{provider}/{rest:path}`, and a privacy gate (`hermie/gate/`) behind it. This page follows one request through it.

## Request path

1. **Route.** `provider` picks the upstream from `ROUTES`: `anthropic` -> api.anthropic.com, `openai` -> api.openai.com, `gemini` -> generativelanguage.googleapis.com, `custom` -> `custom_upstream` (404 when unset). The upstream URL is the base plus the rest of the path and the query string, as the client encoded them.
2. **Refusals.** Paths with `.` / `..` segments or encoded slashes: 400. `/openai/v1/files`: 415. Model listings (`PASSTHROUGH_PREFIXES`) pass only as body-less GET / DELETE, sent with `empty_body()`; everything else must be a JSON object (415 / 400 otherwise).
3. **Walk.** `walker.walk_request` visits every string leaf of a copy of the body, skipping `SKIP_KEYS` outside tool payloads; inside tool payloads it also scans dict keys and numbers with six or more digits. `classify` labels each leaf by author: `user` (user / system / developer messages, system instructions), `tool` (tool results, function responses), `assistant`, `binary` (image data, never scanned) or `other` (tool definitions and metadata).
4. **Scan.** `Gate.scan` (`gate/gate.py`) runs the Presidio analyzer (`gate/recognizers.py`: Presidio recognizers, spaCy NER, `plausible` filters; the Chinese pass is skipped for text without CJK characters) and the regex layer `gate/rules.py` (provider tokens, name-driven secrets, headers and query parameters, entropy tokens, ID numbers, labelled names, English and Chinese addresses; no model, pure functions) over 48 KB chunks, adds every literal occurrence of a value already in the mapping, and replaces findings with `<ENTITY_N>` placeholders (`gate/redact.py`). New placeholders are merged into `mapping.json` under an flock, so two Hermie processes never mint the same name for different values; the file also keeps per-entity counters and a generation, so `hermie forget` never lets a number be reused and a running gate drops its cache. With a judge, `user` and `tool` leaves are also checked for encoded data (`smuggling_risk_text`, or `smuggling_risk_url` for a leaf that is a URL) and then asked to the judge (`gate/judge.py`: `make_judge` picks `ContextualJudge`, a local Ollama chat model, or `LayaJudge`, a fine-tuned Laya decision model through laya-mlx that scores 4000-character windows and keeps the maximum). Results are cached by text hash (`cache_mb`), so a conversation's history is scanned once.
5. **Decide.** Per leaf: placeholders only; a flagged `user` leaf is **held** (the walk stops and the prompter asks: `TtyPrompter` in a terminal, otherwise `ModPrompter`, which waits for the Claude Code menu and falls back to `DialogPrompter`, a macOS dialog; reject means HTTP 422 and the hash goes into `Approvals.dropped`, so the same text in a later request's history is withheld with `DROPPED_NOTE` instead of asking again); a flagged leaf of any other origin is **withheld** (replaced by `WITHHELD_NOTE`); images are withheld unless `images = "pass"`. Items released with `hermie allow ID` (`allowed.jsonl`, full hashes; ids come from `AllowStore.assign`) or "allow everything this session" (judge and smuggling decisions only) pass. With local_model configured the menu also offers "rewrite locally": server.walk passes the raw held text (WalkResult.held_text, memory only) to gate/local.py, which asks the local model for the sensitive spans (only spans that occur literally in the text are kept); `Gate.redact_spans` replaces every occurrence with a placeholder (minted and persisted like any other), and Gate.scan then covers patterns and known values only (an `other` origin, so no judge). The result is shown to the person through `ModPrompter.review` (the ask row has kind `rewrite` and holds it as `preview` until it is answered): send, redo (ask the model again), or discard. On send the text is stored in Approvals.rewrites (memory only, by content hash) and the walk repeats; the walker then substitutes it as a pass decision with reason "local". A failed, empty or too long (over 3000 characters) result, a discard, a timeout and a prompter without a review step are all a reject. Only the Claude Code menu offers it (not the terminal or dialog prompter), and never for a detector error. A judge flag on an `other` leaf is ignored; a detector error is not, and it is never released.
6. **Send.** The rewritten body goes through `certify_body` into a `CleanBody`, is stored as `outbound/<id>.json` (unless `bodies = false`; once over `bodies_keep_mb`, the oldest are pruned down to 90% of it; a failed write is skipped, like a failed receipt write, and the request goes on), and `send_upstream` sends it with the allowlisted headers (`FORWARD_HEADERS`). In `observe` mode the original body is sent and stored.

## Response path

- **JSON replies:** every string leaf goes through `Gate.restore`, which swaps placeholders back from the mapping (`stream.restore_json`).
- **Streams (`text/event-stream`):** `stream.relay_sse` parses each event and restores its data. Text under the streamed keys (`BUFFERED_KEYS`: `text`, `partial_json`, `content`, `arguments`, `delta`, `thinking`, `reasoning_content`, `refusal`) passes through a `PlaceholderBuffer`, which holds back a tail that may be the start of a placeholder until the next event completes it. A held tail is flushed back into the leaf that carried it as soon as a leaf at another path is fed (in the same event or a later one), so the client sees the same events; only when no such event is left does Hermie add one (`hermie_flush`). If the upstream breaks off mid-stream, the held events still go out before the error ends the response. Tool arguments are JSON text (`JSON_TEXT_KEYS`: `partial_json`, `arguments`, and `delta` in a Responses `*arguments*` event), so a value restored into them is JSON-escaped; a quote or a newline in it does not break the call. `restore_json` does the same for non-streamed replies.
- Placeholders put back are counted as `restored` in the receipt; placeholder-shaped tokens that are not in the mapping are left as they are and counted as `unrestored`.
- Response headers passed back: request ids, `retry-after`, rate-limit headers, plus `x-hermie-request-id`.

Every request, refused or not, ends with one line in `receipt.jsonl` (`receipt.ReceiptLine`), written when the response is complete (for streams: when the stream ends or the client leaves).

## Data files

All under `data_dir` (default `~/.hermie`), created 0600:

| File | Holds | Written by |
|---|---|---|
| `config.toml` | optional config, see `config.example.toml` | you |
| `mapping.json` | placeholder -> real value; the most sensitive file | `redact.MappingStore` |
| `receipt.jsonl` | one data-free line per request | `receipt.Receipt` |
| `outbound/<id>.json` | each request body exactly as sent | `receipt.BodyStore` |
| `pending.jsonl` | held / withheld items (hash, id, kind, reason, size; no text), last 500 | `approvals.AllowStore` |
| `allowed.jsonl` | hashes released with `hermie allow` or the prompt | `approvals.AllowStore` |
| `asks.json` | the held item waiting for an answer (id, kind, reason, size; no text); `[]` when none | `approvals.ModPrompter` |
| `answers.jsonl` | answers given with `hermie answer` (id, send / reject / session, time) | `approvals.write_answer` |
| `ui.json` | heartbeat: touched by every `hermie asks`; fresh for 90 s means a menu is polling | `approvals.touch_ui` |
| `judge_cache.jsonl` | judge verdicts keyed by a hash of the judge spec and the judged text (no text) | `gate.Gate` |
| `serve.json` | pid, host, port and start time of the running `hermie serve`; removed on exit | `cli._serve` via `claude_code` |
| `turns/<session>.json` | the time the current Claude Code turn started, per session id (hooks only) | `claude_code` |

`hermie tail` / `stats` read the receipt, `hermie show` reads `outbound/`, `hermie allow` appends to `allowed.jsonl` (picked up by a running proxy on the next request), `hermie asks [--json]` lists the open ask (and touches `ui.json`), `hermie answer ID send|reject|session|local` records the answer that `ModPrompter` polls for every 0.25 s (the Claude Code mod in `integrations/claude-code-menu` uses both), `hermie forget` clears the values in `mapping.json` (counters kept, generation bumped). `hermie hide` adds entries to `mapping.json` under the same lock (a running proxy picks them up on its next scan, also for cached texts).

## Claude Code integration (`hermie/claude_code.py`)

`hermie install-hooks` writes a `statusLine` (`hermie status`) and three hooks (`hermie hook`) into `.claude/settings.local.json` (or `~/.claude/settings.json` with `--user`), merged with what is there and idempotent; `--uninstall` removes only Hermie's entries. `hermie status` prints one line from `serve.json` (is the pid alive, does the port accept a connection; no HTTP probe, which would leave a receipt line per refresh), the size of the mapping and a summary of the last receipt line. `hermie hook` reads one Claude Code event from stdin: `UserPromptSubmit` writes the turn marker, `Stop` summarizes the receipt lines since the marker (replaced counts are the largest single request's, since every request resends the context; restored / held / withheld are summed) into a `systemMessage`, `PostToolUse` for `Write` / `Edit` / `MultiEdit` / `NotebookEdit` reports the `restored` count of the latest such line. A `systemMessage` is shown to the user and not added to the model's context. Everything the hooks print comes from the receipt and the mapping size, never from request text; any failure prints nothing and exits 0.
